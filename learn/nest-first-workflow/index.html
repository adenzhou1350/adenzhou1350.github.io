Nest 上手：添加待办、修改记录和写邮件草稿

先启动本地工作台，试着保存一条待办；接上模型后，再用对话修改记录、起草邮件。

周栩丞 · Aden2026-10-09约 10 分钟

这次用几条虚构事项试试 Nest：添加待办、修改原记录，再保存一封邮件草稿。做完后到对应页面看看，记录是否真的按要求改好了。Nest 目前是个人 alpha 预览版；下面的步骤来自公开项目说明，还没有在所有模型和环境中验证。

1. 启动自己的工作台

装好 Python 3.10+ 和 Git，在准备存放练习项目的目录打开终端：

powershell
git clone https://github.com/adenzhou1350/nest-agent-public.git
cd nest-agent-public
python -m nest.server --port 8765

终端先不要关，用浏览器打开 127.0.0.1:8765。Windows 如果只有 py 命令，把最后一行的 python 换成 py -3。也可以下载仓库 ZIP，解压后双击 打开栖伴.cmd。核心功能无需 pip install，模型服务要另外准备。

练习时只从本机通过回环地址访问，不用配置真实邮箱，也不要导入私人资料。

2. 先手动保存一条待办

进入“待办与日程”，点“添加待办”，保存“整理纸飞机材料”，不设提醒。再打开这条记录，把标题改成“纸飞机材料已备齐”。

  • 这条待办没有变成两条，旧标题没有留下一份副本。
  • 刷新页面或重新打开网页，改后的标题仍然保留。
  • 完成状态和提醒都没有跟着改变。

没有连接模型也能做完这一步。记下手动保存和修改的结果，后面的自然语言操作先记作“未测”。

3. 连接支持工具调用的模型

在“定制我的助手”里打开“连接模型”，填入自己的兼容 API 基础地址和实际模型名。地址通常以 /v1 结尾，不要填聊天网页，也不要填完整的 /chat/completions 路径。

模型需要支持原生 tool_calls。先点“测试填写的连接”，再点“保存我的设置”。连接测试只查询模型列表，能通过不代表工具调用就能用，还要试下一节的操作。如果遇到认证、端口或模型名问题，可以查连接排错说明。密钥不要写进聊天或网址。

工作台数据存在这台电脑上；推理发生在哪里，取决于配置的模型接口。任务文本、上下文和工具结果都会交给这个接口处理。

4. 用对话添加、修改和起草

打开“和我聊聊”，在同一段对话里逐条发送下面的内容。等前一条完成后再发下一条：

text
添加一个待办：准备纸飞机活动说明。不设置提醒。

到待办页看一眼：应该新增了一条，刚才手动创建的事项也还在。

text
把刚才的准备纸飞机活动说明改成核对纸飞机活动说明。
修改原记录，不新增，不设置提醒。

再回到列表，标题应该已经更新，记录数量没有增加。展开执行记录，看看改的是哪一条；如果能看到记录 ID，就比较修改前后是否相同。

text
给 workshop@example.com 起草邮件，主题“纸飞机活动准备”，
正文“材料已经备齐，活动说明还在核对。”
只保存本地草稿，不发送。

打开“邮件草稿”，检查收件人、主题和完整正文。example.com 是示例地址，草稿应保持未发送。它只存在本地，不会自动出现在 Gmail 或飞书的远端草稿箱里。

5. 记录结果，结束练习

记下版本、输入、预期和实际结果，尤其是新增有没有多出一条、修改是否保留了原对象、草稿内容是否准确且未发送。如果某一步超时，先看看记录是否已经存在，再补做缺少的操作，免得重复创建。以这些实际记录为准，不能只看对话里的成功提示。

想继续试资料查询和提醒，可以做六轮演练，记得把其中的历史日期换成自己的未来日期。练习结束后，在启动服务的终端按 Ctrl+C 退出；只关闭网页，服务还会继续运行。
