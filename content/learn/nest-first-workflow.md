让 Agent 说“完成了”很容易，确认它改对了记录才是这次练习的重点。我们用虚构事项走一遍创建、修改和保存草稿，逐步核对实际结果。Nest 当前是**个人 alpha 预览版**；以下步骤依据[公开项目说明](https://github.com/adenzhou1350/nest-agent-public)，不代表所有模型与环境都已通过验收。

![Nest 公开开发界面，使用合成示例展示个人工作台](/assets/images/nest-overview.jpg)

## 1. 启动自己的工作台

准备 Python 3.10+ 和 Git，在用于练习的目录打开终端：

```powershell
git clone https://github.com/adenzhou1350/nest-agent-public.git
cd nest-agent-public
python -m nest.server --port 8765
```

保持终端开启，浏览器访问 [127.0.0.1:8765](http://127.0.0.1:8765)。Windows 若只有 `py` 命令，把最后一行的 `python` 换成 `py -3`。也可以从仓库下载 ZIP，解压后双击 `打开栖伴.cmd`。核心无需 `pip install`，模型服务需要另行准备。

这是本机个人工作台，先保持回环访问。不要为这次练习配置真实邮箱或导入私人资料。

## 2. 没有模型，也先检查保存

进入 **待办与日程 → 添加待办**，手动保存“整理纸飞机材料”，不设提醒。打开它，改名为“纸飞机材料已备齐”。

- 列表中应该仍是同一条记录，旧标题没有留下一条副本。
- 刷新页面或重新打开网页，修改后的标题应继续存在。
- 完成状态和提醒没有被意外改变。

记下这个结果。它验证的是手动存储流程；尚未连接模型时，后面的自然语言步骤记作“未测”。

## 3. 连接支持工具调用的模型

在 **定制我的助手 → 连接模型**，填入自己的兼容 API 基础地址与实际模型名。地址通常以 `/v1` 结尾，不是聊天网页，也不是完整的 `/chat/completions` 路径。

模型需要支持原生 `tool_calls`。先点 **测试填写的连接**，再点 **保存我的设置**。这个测试只查询模型列表，**通过不等于工具调用已经通过**，还要完成下一节的操作。认证、端口或模型名问题可按[连接排错说明](https://github.com/adenzhou1350/nest-agent-public/blob/main/docs/model-connection.md)处理；密钥不要写进聊天或网址。

数据保存在工作台电脑，不代表推理也在本机。任务文本、上下文和工具结果会交给你配置的模型接口处理。

## 4. 每做一步，就核对一次

进入 **和我聊聊**。在同一对话中逐条发送，前一条完成后再继续：

```text
添加一个待办：准备纸飞机活动说明。不设置提醒。
```

到待办页确认新增了一条，手动创建的事项仍然存在。

```text
把刚才的准备纸飞机活动说明改成核对纸飞机活动说明。
修改原记录，不新增，不设置提醒。
```

再次查看列表，确认标题更新且数量未增加；展开执行记录核对修改对象，能看到记录 ID 时比较是否相同。

```text
给 workshop@example.com 起草邮件，主题“纸飞机活动准备”，
正文“材料已经备齐，活动说明还在核对。”
只保存本地草稿，不发送。
```

在 **邮件草稿** 核对收件人、主题和完整正文。`example.com` 是示例地址，草稿应保持未发送。它只存在本地，不会自动进入 Gmail 或飞书的远端草稿箱。

## 5. 留下可复查的结果

记录版本、输入、预期和实际结果：新增是否只有一条、修改是否保留原对象、草稿是否准确且未发送。遇到超时先查看记录，再补缺项，避免重复创建。不要只凭对话中的成功提示判定通过。

需要继续练习资料查询和提醒，可读[六轮演练](https://github.com/adenzhou1350/nest-agent-public/blob/main/docs/try-it.md)。其中历史日期要换成自己的未来日期。终端启动的服务，等任务结束后按 `Ctrl+C` 退出；关闭网页本身不会停止服务。
